#ToolScore7-day

Score = 40% GitHub repo-count growth (topic-tagged repos, via the GitHub API) + 30% Hacker News comment-count growth (via the Algolia HN Search API) + 30% Google Trends search interest, 0–100 (via a third-party Trends proxy - see the README for the reliability caveat on that one). Growth compares each week's snapshot against whichever earlier snapshot is closest to 7 days prior, not just the previous row, so an off-schedule manual run doesn't get compared against a too-recent point. Growth terms are then clipped to ±50% before blending, so one noisy week can't dominate the score. A tool without Google Trends coverage (currently Cursor - "Cursor" is too generic a search term to track cleanly) uses the average of the other tools' actual Trends values that week for that third, instead of an arbitrary fixed number. A tool with no GitHub signal at all (currently Replit Agent, Devin, and Lovable - not tools people build a public GitHub ecosystem of extensions/example repos around the way an IDE or CLI is, so a repo count would be thin or actively misleading rather than just missing) skips that term entirely and reweights to 50% Hacker News + 50% Trends, rather than scoring it on a number nobody actually measured. This is a first-pass formula — worth revisiting once there's more than a few weeks of history to check it against.

Momentum recalculated every Monday alongside the trends data refresh.
